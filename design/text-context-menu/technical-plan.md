# 文本选区右键菜单技术方案

本方案为 HTML 审核阶段的实施预案。用户通过本次设计稿后再进入测试用例审核和 TDD；当前不修改生产源码。

## 组件与菜单接入

在 `src/lib/desktop` 增加统一文本上下文控制器与适配器，覆盖原生文本控件、contenteditable/composer、预览 DOM Range、Monaco 模型选区。文档级委托使动态业务面板和 Portal 自动接入，不复制或重建 ChatPanel、MarkdownEditor 与 29 类业务面板。预览依据已有 `data-text-preview` / `data-text-input` 和实际可选取边界识别；禁止把非正文 UI 当作预览。

扩展现有 `desktop/shared/input-context-menu.ts`、`desktop/main/input-context-menu.ts`、preload 和 IPC 受限协议，加入引用、纯文本粘贴、删除及分隔结构。主进程只接收能力布尔值、菜单位置/来源与请求标识，返回允许的命令 ID；文本/Key/chip 元数据留在渲染端。调用必须绑定发起窗口、主 frame 和活跃请求，销毁/失焦/替换后释放 pending promise。

菜单来源类型与命令启用能力分别判断：撤销/重做分组仅输入框和编辑区显示，普通预览/消息等非编辑文本省略整组。只读输入框保留两项但禁用，不能仅用 `editable=false` 判定隐藏。依据实际非空分组生成分隔线，避免历史组移除后留下空分组或连续分隔线。

普通可读取范围的控件沿用现有命令目标和 `nativeTextEdits`；预览只开放读取与区域全选，复制使用精确快照。对于无 `selectionStart` 的原生控件，必须补充 Electron `context-menu` 的原生编辑能力来源与操作通道，不能直接忽略 email/number/date，也不能用错误的整框值代替选区。此时 Electron 原生事件自带的 `selectionText` 可以临时存在主进程内存；通过同窗口、同主 frame、同请求标识且来源已确认非敏感的受限通道回传所选文字，并在请求结束释放。渲染端打开菜单的请求仍只含能力和标识，密码/Key一律禁止引用回传，所有选区文字禁止日志或持久化。

Monaco 通过已安装版本的 `onContextMenu` / `getSelection(s)` / `model.getValueInRange` 接入，执行编辑器动作而非隐藏输入框编辑；统一菜单在实际文本区接管，避免内置菜单同时打开。查找框、评论 ViewZone 和编辑器非文本 UI 仍分别识别，保留已注册 Markdown/Monaco 命令、模型版本和撤销栈。接管时需保留现有正文编辑器有用的专属菜单动作，不能为此次修复删除功能。

## 选区与执行守卫

建立不可变快照：文本来源身份、内容/模型版本、输入范围和方向或 DOM Range 端点、窗口/对话/作品身份、事件 epoch、可执行命令。右键 pointerdown 的 epoch 应先建立后捕获本次快照；不能误把打开菜单本身计为使快照失效的交互。

静态文本读取需将选区与本次来源内容 Range 求交：用户消息整段选取的端点可能位于父容器，不能仅以两个端点均被 `contains` 判定。仅提取交集的可见文本，排除相邻消息，保留渲染后的段落换行与原选择方向。此规范化仅用于只读文本读取，不能因此放宽可编辑来源/Monaco 的命令所有权或异步守卫。

菜单返回时先验证同一请求和同一来源，再验证源内容、选区、编辑状态和目标对话身份。DOM MutationObserver、输入/组合事件、会话订阅和窗口生命周期使 ABA 回到相同内容或相同会话也不能复活旧请求。对可编辑来源使用真实 Chromium 或 Monaco 操作，保持受控 React 状态、撤销和原选区方向，不以直接赋值绕过编辑事件。

复用 `composer-editor.ts` 的原生撤销路径，在真实 ChatPanel 内提供仅准备草稿的引用入口。引用正文来自源快照，目标草稿在提交前复核身份与可编辑性。追加纯文本 Markdown 引用，原草稿里的实体 chip 保持不变；源选区里的 chip仅提取可见标签用于引用，基本剪切/复制仍保持既有序列化格式。源是 composer 时先快照后追加，不能重复读取已变化的选择。无模型不禁用准备草稿；模态框禁止背景编辑时引用不可用。

## 审核与验证顺序

调研和产品设计先完成；独立子代理审核本方案及源码范围，再审核 HTML。用户通过 HTML 后，完善测试用例并由独立子代理审核；先运行覆盖当前缺陷的失败测试，再实现；独立 code review 后执行专项、全量单元/集成/浏览器、构建与实际目标系统验证。

HTML 验证只证明审核稿功能和布局，不当作安装版或原生菜单验收。真实验证要选择文本、单击右键、看到原生菜单并执行各项操作，核对剪贴板/草稿/正文/撤销；不能仅查询菜单模板或模拟 IPC 回传即标为通过。敏感数据与真实 Key 不进入源码、日志或证据，使用隔离数据目录与合成文本。Windows 与 macOS 分别记录；没有真实目标机器则保留对应平台待验收。
