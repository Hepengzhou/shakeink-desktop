# 文本选区右键菜单产品设计

任何已有可选取文本都应在单次右键后打开对应的文本菜单。菜单首项为“引用到对话”，其后提供文本基本操作；可用状态取决于本次右键的文本来源、选区和编辑能力。此次修复保留真实业务组件、现有文本选取策略和正文评论行为。

## 覆盖范围

覆盖 AI 用户消息与回复、消息中的 Markdown 和代码、AI 输入框、全部普通文本输入框、contenteditable、Markdown 预览、正文预览、评论内容、卡片摘要和其他已允许选取的文本。包含对话框/浮层中的输入框、只读及允许选取的禁用控件、email/number/date 等原生控件。

Markdown 编辑器继续使用真实 Monaco。编辑器内的文本选区使用同一菜单信息结构，编辑命令由 Monaco 模型执行；查找框、评论输入区仍按普通输入控件处理。按钮、导航标题和其他原本不可选取的 UI 不扩大为正文；卡片边框和非文本右键继续服从原有业务菜单。

## 菜单信息结构

| 分组 | 顺序 | 项目 | 可用条件 |
| --- | --- | --- | --- |
| 引用 | 1 | 引用到对话 | 有属于本次来源的非空选中文字、非密码/Key，并且当前对话可准备草稿 |
| 历史 | 2 | 撤销、重做 | 仅输入框和编辑区显示；来源支持且存在相应编辑历史时可用；只读输入框禁用 |
| 剪贴板 | 3 | 剪切、复制、粘贴、粘贴为纯文本 | 剪切需可编辑且有选区；复制需有选区；粘贴需可编辑并支持该操作 |
| 选区 | 4 | 删除、全选 | 删除需可编辑且有选区；全选针对本次文本区域 |

按实际显示的分组插入分隔线。AI 对话、Markdown 预览、正文预览、评论原文和卡片摘要等非输入框、非编辑文本不显示“撤销”“重做”及历史分组。输入框和编辑区保留历史分组，无对应历史或处于只读状态时置灰；只读输入框仍属于输入框。只读预览中不能执行的剪切、粘贴、删除置灰，有选区时引用、复制、全选可用。无选区仍打开菜单，引用、复制、剪切、删除置灰，可编辑来源继续提供粘贴和全选。

正常密码框不开放密码复制或引用。明确标记的 API Key 控件保留已批准的复制、剪切、粘贴行为，引用置灰。菜单只显示操作名称，不显示 Key、密码或选中文字。

快捷键提示来自当前平台的命令绑定，不能把设计稿里 Windows 的 Ctrl 硬编码到 macOS。没有绑定的“引用到对话”不虚构快捷键。多绑定、冲突转移和录制行为保持原设置约定。

## 右键与选区

1. 用户拖选、双击选词或键盘选取后，在选区内单次右键打开一个菜单。右键不得先折叠原选区，不得触发卡片导航、拖拽或评论提交。
   用户发送的聊天消息与 AI 回复均可复制选中文字，三击整段/整条消息也应正确识别。浏览器将段落选区边界放在父容器时，按本次文本来源规范化边界，不能误判为空；跨来源选区仅取本次右键来源内的选中文字，不混入相邻消息。
2. 右键到另一文本区域时，操作目标属于新的区域，不复用旧消息或旧输入框的选区。右键到同一区域的未选中位置时采用该控件正常光标行为；没有有效选区则展示无选区状态。
3. 菜单打开时记录来源、选区方向、内容版本和对话身份。取消菜单不改变草稿或正文；普通输入和 composer 保留焦点、光标与撤销记录。
4. Esc、点击菜单外、窗口失焦、来源卸载或会话切换关闭菜单。迟到返回的菜单选择失效，不对新的焦点或新会话执行操作。
5. 菜单键和 Shift+F10提供等价入口；位置靠近当前选区或光标。屏幕边缘自动避让，缩放、滚动、窄窗口、Dialog/Portal 均不得裁切菜单。

## 引用到对话

执行后保留源文本，将选中文字逐行加 `> ` 转为 Markdown 引用，追加到当前草稿末尾，按需要补空行。已有草稿、未发送文字和实体引用 chip 原样保留；输入框可见并聚焦，光标落在引用后的新空行，作者继续写自己的要求。

引用显示用户选中的可见文字，保留换行、Unicode 和选中的空格。不复制 HTML、图片、隐藏元数据或未选中的整条消息。AI 输入框里的实体 chip 若包含在选区中，引用其可见标签为普通文本，不额外携带实体身份。剪切、复制和粘贴仍沿用原有 chip 序列化与编辑契约；引用的纯文本规则不改变这些基本操作。

若从 AI 输入框本身引用，先保存原选区快照，再追加引用，不删除原文，不因目标光标变化引用错位。重复明确点击引用允许形成多个引用，取消不追加。

引用本身不自动发送、不创建 AI 回合、不调用模型、不消耗 Key；无模型时仍可准备草稿，发送继续受原模型门控。没有可用的对话草稿、输入法仍在组合或当前对话处于禁止编辑状态时，引用置灰。对话面板隐藏时可以展开已有面板；不覆盖或重置其他会话。Dialog 禁止操作背景时仍可用基本编辑命令，引用置灰，不因引用擅自关闭未保存表单。

跨作品引用只传选中的普通文本，不隐式迁移实体身份，不自动切换作品或创建会话。菜单打开后会话/作品身份变化即取消；需要另一作品上下文时由作者自行选择。

## 视觉与 HTML 审核稿

HTML 审核稿采用宣纸/玄墨现有色系，清楚展示可用项、禁用项、分组、快捷键和引用后的草稿。初始展示正文选区和菜单；支持 AI 消息、composer、普通输入框、Markdown、正文、只读输入、无选区与敏感控件场景，以及真实鼠标拖选、右键、菜单外关闭和键盘菜单操作。

正式产品使用 Electron 原生菜单。HTML 菜单是可交互的结构示意，最终边框、行高、系统主题、圆角和关闭动画随 Windows/macOS 原生实现；不把审核工具栏或示例正文带入安装版。预览区域复用真实 `MarkdownPreview`，审核用编辑控件仅展示菜单与引用效果。

## 验收要求

| 验收项 | 通过条件 |
| --- | --- |
| 逐类覆盖 | 每类文本单次右键弹出菜单；Dialog、卡片、消息代码与正文跨段选区分别验证 |
| 引用 | 精确选区写入草稿，原文不变，原草稿/chip 保留，无自动发送，取消和迟到操作无副作用 |
| 基本操作 | 用菜单复制、剪切、粘贴、纯文本粘贴、删除、全选；撤销/重做保持真实历史 |
| 只读与敏感 | 只读不写入；密码/Key不被引用；API Key原批准编辑能力不回归 |
| 历史分组 | 非输入框、非编辑文本没有撤销/重做；输入框和编辑区保留，依据真实历史与只读状态启用或禁用；无空分组或连续分隔线 |
| 所有权 | 多窗口、A→B→A 会话切换、DOM 卸载、输入法、异步剪贴板与选区变化拒绝迟到操作 |
| 共存 | 评论浮钮、卡片打开/拖拽、正文编辑、模型门控和快捷键继续工作；不出现双菜单 |
| 目标系统 | Windows Electron 逐场景原生验收，离线启动；macOS 使用真实目标机器，未执行须保留待验收 |

本次按用户指定顺序交付：调研 → 产品设计 → HTML 用户审核 → 实现 → 测试 → 总结。审核前仅新增设计产物和验证设计稿的脚本，不改变生产组件或声称产品测试通过。
