v2按最新用户反馈修订：亮灰Logo、更舒展的烟气、四按钮统一底色、单色面性图标；新增参考与技术说明见 [v2修订方案](./revision-v2.md)。v1存于 `archive-v1/`，旧彩色卡片方案已被本稿覆盖。

## 1. 范围与空态判定

仅调整 AI 面板的纯净空态。正式实施仍复用真实 `ChatPanel.tsx` 与 `components/chat/*`，不能把 HTML 导入安装版。

欢迎区显示条件应为：消息加载已完成且消息数为零，同时没有生成/运行、`creatingNovel` 建书过程、待回答问题、待批准计划、选卡占槽、待确认请求、任何待发队列（包括暂停队列）、执行恢复或错误。加载显示加载状态；错误显示错误/重试；各操作状态继续显示原面板。仅检查 `messages.length===0` 不足以覆盖这些边界。

进入首条消息后欢迎区消失；composer 保留 DOM、焦点、引用 chip、草稿、输入法组合和撤销状态。禁止为空态和非空态各复制一份 composer。

## 2. 视觉与布局

中央欢迎区和底部输入区分别布局。面板：header / 可滚动剩余空间 / shrink-0 composer。保留原 ChatPanel 44px 顶栏布局空间，纯空态不添加新标题或会话按钮。欢迎块在剩余空间水平、垂直居中；空间不足时从顶部开始并可滚动，composer 始终可见。

| 元素 | 规格 |
| --- | --- |
| Logo | 128px透明画布，现有品牌SVG灰阶变体；烟有足够向上/横向舒展空间；独立于标题上方 |
| 标题 | 无作品：“今天，想写点什么？”；已有作品：沿用真实作品问候；30px/1.5，字重400，窄栏27px，极窄23px |
| 说明 | “故事、世界与人物，都从一个念头开始。”；12.5px，辅助文字色 |
| 中央组宽度 | 最大480px；左右至少24px；居中 |
| 创建作品 | 占按钮组整行，74px高，28px图标；标题15px；副文案“开启一段新的创作” |
| 次按钮 | 新世界观 / 新角色 / 新场景，三等列，58px高，22px图标；横排图文、12px文字；无额外段落 |
| 按钮间距 | 行列10px；标题区至按钮组32px；极窄列距6px |
| 输入区 | 最大800px、两侧28px、距底部20px；短窗最少12px；圆角20px，极窄16px，无悬浮厚阴影 |
| 字体 | 两主题统一系统中文无衬线，保持排版骨架与换行一致；无在线字体 |

面板宽度≥600px使用正常字号与间距，<600px收缩 welcome 宽度；≥320px仍保持三次入口同排，按钮文字不截断。短窗压缩Logo画布至88px、间距与按钮高度，出现冲突则欢迎区滚动，不能覆盖输入区。本轮仅呈现对话区域，外围审核工具与说明不属于产品 UI。

## 3. 动作契约

| 入口 | 正式产品意图 | 无作品时 | HTML 审核稿行为 |
| --- | --- | --- | --- |
| 创建作品 | 打开现有创建作品向导 | 可用 | 打开注明“交互示意”的流程说明弹窗，不假造落库成功 |
| 新世界观 | 进入所选作品的世界观新增流程 | 先选择作品或进入创建作品 | 显示“先选择一部作品”说明与创建作品入口 |
| 新角色 | 打开所选作品的现有角色新增流程 | 同上 | 同上，说明目标为角色 |
| 新场景 | 打开所选作品的现有场景新增流程，默认根节点 | 同上 | 同上，说明目标为场景 |

已有空会话绑定作品时，不能直接把另一个作品挂到旧 conversationId。创建新作品应走已有新会话/向导请求机制；副入口优先当前会话已绑定作品，不能误用其他 Tab 的作品。无模型不阻止查看创作入口；实际 AI 执行仍由原模型门控负责，实体手动创建不应要求模型。

具体复用：作品调用 `CreateNovelDialog` 单页模板向导，已有草稿先确认替换，准备新会话、不自动发送，首次发送前才落库；世界观创建根节点（名称必填≤100字，`parentId:null`）；角色沿用直接创建“新角色”及 `PROTAGONIST` 初始类型、打开详情；场景沿用名称对话框（必填≤50字、根节点 `parentId:null`）。待创建作品不算已关联的有效实体归属，需要先完成作品创建。正式技术方案应以现有 `draftNovelId → hero选择 → conversation/active tab` 解析为基础，并对已绑定会话保留现有一致性守卫。

底部原有模型、模式、上下文/引用、添加菜单、作品关联、发送/停止、快捷键提示全部保留。图片/附件及会话引用当前源组件标记“即将支持”，不能设计成已可上传。原型只展示无模型、无关联作品的空状态，输入可编辑；点击模型、模式、引用等打开明确的交互边界说明。不接真实服务，不允许输入 Key。发送保持禁用并说明需配置模型，不输出假回复。快捷键文案正式接入已提交设置，本稿不硬编码假设快捷键。

## 4. 帧动画规范

使用实际离散精灵帧，而不是整体旋转/浮动来冒充帧动画。首帧静止；鼠标进入图标或所属按钮时播放，键盘 focus-visible 同样触发。移开或失焦恢复首帧，离开浏览器页面暂停并复位。

| 对象 | 运动 | 帧规范 |
| --- | --- | --- |
| 玄印 Logo | 原SVG烟形明显横向回旋、向上舒展，连续弯曲原烟轮廓，炉身固定 | 64帧 / 4秒 / 16fps，hover循环 |
| 作品 | 单色书页符号，局部翻页 | 24帧 / 1.2秒 / 20fps，hover循环 |
| 世界观 | 单色星球，轨道点运行 | 同上 |
| 角色 | 单色人物，头部微动 | 同上 |
| 场景 | 单色山峦与日轮，太阳轻升回落 | 同上 |

双主题精灵分别配色；透明背景。静态帧直接提取同一序列。Logo首帧只允许灰阶换色和扩展统一画布，保持原轮廓；局部位移在烟与炉交界处衰减到零，不重画香炉。烟幅度较v1明显扩大，不叠加额外烟迹。`prefers-reduced-motion: reduce` 或审核“减少动态”启用时全部停在首帧，hover填色和焦点仍保留。初始加载、隐藏时不持续播放。没有声音、自动视频、外部 CDN 或供应商请求。

## 5. 技术方案与交付结构

本轮仅制作纯 HTML/CSS/JS 审核稿，直接 `file://` 打开，所有资产在同目录内。审核工具提供双主题、宽屏/分栏/窄栏、短窗、减少动态和设计说明；其 DOM 与产品面板分离。`build-assets.mjs` 从真实品牌 SVG 与自绘图标生成 PNG 精灵，`preview.js` 根据 hover/focus 与逐帧计时切换帧。

先独立子代理审核本文，再建立并审核预览验证用例，然后实现设计稿，独立代码/设计审查，运行本地浏览器检查并人工查看截图。预览验证结果单独保存，不算作全量业务测试；等待用户 UI 审核后才进入正式技术方案/TDD/真实系统验收阶段。
