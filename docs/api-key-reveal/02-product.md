# API Key 回填与明文/密文切换产品设计

日期：2026-10-15。调研依据：`docs/api-key-reveal/01-research.md`。范围仅含配置模型对话框的 API Key 字段（设置面板与引导流程复用同一组件）。

## 1. 用户故事

作者编辑一个已保存的模型时，需要确认当前用的是哪把 Key（例如更换供应商账号前核对尾号），也需要能复制这把 Key 迁移到别处；同时默认不能让它以明文暴露在屏幕上或被随手复制走。

## 2. 功能规则

### 2.1 回填

- 打开"配置模型"编辑已保存的模型时，API Key 输入框显示**已保存的真实 Key**，默认密文（掩码圆点）呈现；输入框不得为空。
- 新增模型（无已存 Key）时输入框为空，占位文案"请输入 API Key"，眼睛按钮照常可用。
- 回填失败（如系统密钥保护不可用）：输入框为空并显示原占位"已配置，留空保留原密钥"，保存语义与现状一致（保留原凭据）。不弹错打断编辑。
- 回填是异步读取；读取返回时若用户已手动输入或已切换供应商/协议/端点，则丢弃迟到结果，不覆盖用户输入。

### 2.2 明文/密文切换

- 输入框右侧内嵌一个眼睛图标按钮：
  - 密文形态（默认）：闭眼图标（EyeOff），输入框 `type="password"`。
  - 明文形态：睁眼图标（Eye），输入框 `type="text"`，显示真实 Key 全文。
- 点击按钮在两种形态间互切，图标随当前形态变化；按钮带 `aria-pressed` 与动态 `aria-label`（"显示 API Key"/"隐藏 API Key"）。
- 切换只改变显示形态，不改变输入框的值、光标所属字段内容或草稿状态；表单忙碌/禁用期间按钮随表单一并禁用。

### 2.3 复制与右键菜单

| 能力 | 密文形态 | 明文形态 |
| --- | --- | --- |
| 显示 | 掩码圆点 | 真实 Key |
| 快捷键复制/剪切 | 无效（静默不执行） | 生效（原生文本行为） |
| 右键菜单【复制】/【剪切】 | 不可点击（禁用态） | 可选中时有选区即可点击 |
| 粘贴 | 可用（不变） | 可用（不变） |
| 引用到对话 | 不可用（不变，两种形态均禁用，防止 Key 泄露进对话） | 不可用 |

- 密文态的不可复制同时由三层保证：键盘命令 `enabled` 判定、剪贴板执行层 `available` 判定、右键菜单能力布尔值——同一规则，菜单只是展示层。
- 明文态的复制/剪切不再走 API Key 专用异步剪贴板桥，与普通文本输入一致（原生 copy/cut；右键菜单复制仍经本地剪贴板桥写入）。

### 2.4 保存/测试/发现语义

- 值未被修改（仍等于回填的 Key）时，保存按"未改动凭据"处理：主进程保留原加密凭据、不提升 `authRevision`；测试连接/刷新目录回退使用已存凭据。
- 值被修改后按新 Key 处理（现状语义：重新加密、提升授权版本）。
- 用户清空输入框后保存，等价于旧占位语义"留空保留原密钥"（范围未变时）。
- 切换供应商/协议/端点清空 Key 的既有规则不变。

## 3. 界面文案

- 按钮 `aria-label`：密文态"显示 API Key"，明文态"隐藏 API Key"。
- 占位文案不变：编辑已保存模型且值为空时"已配置，留空保留原密钥"，否则"请输入 API Key"。
- 不新增其他可见文案；错误提示沿用现有保存/解密失败文案。

## 4. 验收对照

| 验收点 | 判定 |
| --- | --- |
| 再次打开编辑对话框，API Key 不空、密文显示 | 回填值等于已保存 Key 且 `type="password"` |
| 眼睛按钮切换图标与文本形态 | 点击后 `type` 与图标互变，值不变 |
| 明文可复制 | 明文态菜单【复制】可点且能写入剪贴板；快捷键复制生效 |
| 密文不可复制 | 密文态菜单【复制】禁用；快捷键复制无效果 |
| 右键菜单体现两种形态区别 | 同一菜单【复制】按形态启用/禁用 |
| 回归 | 保存/测试/发现/引导语义不变；未修改的 Key 不提升授权版本 |
