# AI 对话首屏正式接入方案

日期：2026-10-12。依据：用户本轮“UI 审核通过，可以继续”；审核基线为 `design/chat-empty-state/product-design.md` v3.4 与对应 HTML。此文是实施方案，不声明完成。

## 范围与组件来源

仅替换真实 ChatPanel 的纯净空态展示，继续使用同一个 contenteditable、所有原输入事件、引用 chip、业务占槽、队列、消息和44px原生标题栏。欢迎组件不含输入框或模拟业务数据。原 HTML、审核工具、401条演示模板数据均不进入运行时。21张批准资产复制为公共静态资源，记录文件尺寸和 SHA-256；不改品牌源图、不调用外部生成服务。

欢迎条件以纯函数实现：恢复完成、消息零条、未加载/加载失败、未生成/建书/跟随/执行恢复、无待答问题/批准计划/待确认请求、无当前作品与会话的选卡、无任何实际队列项、无恢复/存储通知、无活动 SOP 或进程。`queuePaused=true` 且队列为空是当前恢复的正常状态，不能单独挡住欢迎页。存在业务状态时显示原真实消息/占槽/提示，不能因零条消息隐藏它们。会话加载失败增加受导航所有权约束的持续错误状态与重试提示；成功加载、新草稿导航和重置清除，旧请求不能覆盖新状态。

## 布局和动画

新增 `components/chat/ChatEmptyState.tsx` 和局部样式，以真实纸/墨主题变量呈现。四功能卡等高114px，480px以上两列，以下单列；三题材卡在末行。欢迎区滚动，composer固定底部；七卡组与空态 composer 同宽、最大800px，消息态保留原960px及进程水槽。关联作品行位于 composer 上方。改变欢迎状态只改变兄弟内容与样式，输入框节点持续保留。

静态图标每枚单色且四枚颜色不同。四右图统一低亮半透明，纸主题灰度后 sepia(.5)，墨主题灰度；悬停或键盘 focus-visible 展开0→12并保持，二者均解除时从当前连续位置倒放→0，不循环。Logo原香炉64帧烟动画仅交互时循环。一个共享 RAF 直接更新背景位置，无逐帧 React setState；空闲停止。减少动态、窗口 blur、document.hidden、所有真实模态及组件卸载清零并停调度，恢复后按有效触发重新开始；监听完整清理。题材卡仅轻微推近，暂停规则一致。动画状态机提取纯函数以验证中途换向与时间积分。

## 入口与业务契约

ChatPanel 持续挂载真实 `CreateNovelDialog`，仅增加可选 `initialPreset`（仙侠/历史/科幻）。每次由关闭到打开时初始化独立 Set 和空白选卡，不在作者编辑途中重复套预选。原 SidebarTree 调用不传 preset，始终打开默认筛选；保留真实本地启用模板目录、加载/失败门控、过滤、详情、两步替换与 requestNewConversation，不引入预览模板数据。三个题材的男频/长篇/题材和四组标签按批准 v3.4 预选，均可编辑。确定仍准备新会话并解除旧作品关联，不发送、不创建数据库作品；首次有效发送才走原延迟建书流程。

角色/世界观/场景用批准提示词。空草稿直接插入，非空追加两个换行，已含完整模板则仅聚焦。对原 contenteditable 在末尾使用原 `insertDraftAtCaret` 并同步 store，保留现有 chip DOM 与 Chromium native undo，不重建整个草稿，不发送。输入法组合期间禁用快捷入口或延迟到 compositionend，避免截断尚未确认的文字；被 modal/不可编辑状态挡住时不改草稿。

无模型允许准备草稿，但不能发出新回合：抽取 ModelPicker 原 `chat-models` 查询为共享 hook，不选择目录首项或响应默认值。真实所选 ID 在目录中才启用发送。发送按钮、命令、handleSend 和 sendText 最前端（早于 POST /api/novels）检查；自动队列在移除队首之前检查实时 store 和查询缓存，目录/选择变化触发重评估。维持继承默认值的 modelChoiceExplicit=false 与服务端原子快照；历史重试、恢复及计划批准保留原回合与后端校验。

## 文件分工与验收

主代理：ChatPanel、共享模型查询、加载错误、向导预选、业务纯函数、台账、全量测试与 Windows Electron 验收。
独立实现代理：仅新欢迎组件/局部 CSS/动画 hook/批准公共资源及资源清单，保留他人文件。
独立审核代理：方案→用例→代码只读审核；严重问题修复后复审。

先写新增单元/真实组件浏览器用例并记录 RED，再实现并记录 GREEN。测试覆盖空态守卫各业务状态、七入口、预选生命周期、草稿保留/重复/引用/撤销、无模型和队列防丢、导航错误所有权、双主题与窄/短窗口、动画方向/生命周期。已有单元、集成、浏览器回归全量执行。随后串行构建 UI 和 Electron，在隔离临时目录中启动真实 Windows Electron，离线检查七入口、无模型门控、双主题/布局/原生事件、截图证据。浏览器 fixture 只作为组件测试，不能冒充业务端点或真实供应商验收。没有供应商 Key 的真实生成不声明通过；Mac 验证不以 Windows 或主题切换代替。

更新 implementation-boundaries、requirements-traceability、migration-map 以记录最新批准范围、实际模块与证据。最终汇报真实完成和限制，不安装覆盖用户当前程序、不修改真实数据、不提交或发布。
