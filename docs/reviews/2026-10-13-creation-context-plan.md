# 小说创作向导上下文修复方案

为 `deepseek-flash` 和 `deepseek-v4-pro` 恢复官方 1M 输入窗口，使新建与已保存的官方模型配置可以运行完整创作工具链。保留原上下文安全检查、作者审批、目录授权和真实业务组件。

## 实现

1. 在 `desktop/shared/provider-capabilities.ts` 精确登记两型号 `contextWindow: 1000000`，新建配置经现有目录解析与保存流程获得容量。
2. 在同模块提供受端点范围限制的容量查询：仅 `provider=deepseek`、文本类、OpenAI 协议、官方 HTTPS 主机、已支持路径和精确型号可继承此容量。带用户信息、查询、片段、非默认端口、代理主机、不同路径和其他供应商均不能继承。
3. `desktop/service/models.ts` 的 `localModelRecord` 依次使用明确配置、受范围限制的官方容量、现有未知模型 16000 预算。已有 0 容量配置无需删除重建；不写回旧配置，不改变 model ID、authRevision、Key、端点或 immutable public snapshot。
4. 若真实完整创作流程暴露其他阻塞，先补充该阻塞证据与用例，再修复；不靠降低校验标准或伪造回执通过验收。

## 顺序

方案独立审核后编写测试用例并独立审核；先执行失败回归测试，再实现；子代理 code review；运行专项与全量单元、集成、组件测试及实际 Windows Electron 验证。完整供应商验收使用指定型号从向导逐步至正文，核对真实保存与重开读取。

新目录项有精确容量，旧官方 0 配置得到同一运行预算，显式小容量和未知供应商继续受原安全限制。实际 `/models` 与调用证明型号可用。向导首发不报截图错误，所有创作阶段以真实业务写入、检查点及审批推进至正文，重开仍可读。记录每阶段与命令结果，不能以单次启动、mock 或未执行项目替代完整验收。
