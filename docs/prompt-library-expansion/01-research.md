# 剧情提示词模板库扩充调研

2026-10-14。目标是让作者在原创作向导中选择可直接拼贴的剧情模板，覆盖用户列出的通用结构与八类题材套路。模板采用原创中文操作指令，复用仓库真实 React 向导和离线模板库。

## 现有产品与缺口

`src/lib/creation-wizard/templates/index.ts` 汇总 401 条模板：主题 120、世界观 122、角色 69、剧情 90。`filter.ts` 用频道、题材、篇幅和标签过滤；空频道与空题材数组表示通用。`compose.ts` 把所选原文放进作者草稿，不自动发送。`desktop/service/template-library.ts` 在启动时按稳定 ID 和默认 hash 更新精确旧默认，保护作者修改和停用状态。

现有剧情偏网文流派，缺少完整的经典结构和爱情、推理、科幻等专门机制。原始库没有重复 ID 或完全相同的正文，但 `plot-three-act-skeleton` 与 `plot-generic-mainline` 同名且执行相同任务；若干掉马、囤货和追悔条目仅改变人物或场景，需要明确不同的目标、推进和交付物。跨类别同名不等于同一模板，主题、世界观与人物的创作任务仍需清晰区分。

## 结构依据与产品解释

| 方法 | 调研结论 | 模板落点与依据 |
| --- | --- | --- |
| 英雄之旅 | Campbell 基金会强调离 departure、启蒙 initiation、归 return 三大运动，可作象征性成长过程。 | 聚焦跨界、试炼、所得与回归社会的改变。[Joseph Campbell Foundation](https://www.jcf.org/learn/joseph-campbell-heros-journey) |
| 作家之旅 | Vogler 将神话旅程转为编剧操作框架；与 Campbell 方法属于同一谱系。 | 用日常世界到携药归来的十二阶段组织具体场景，并检查导师、门槛守卫等角色功能。出版依据为 Christopher Vogler《The Writer's Journey》第三版，Michael Wiese Productions，2007；本次指令为原创改编，不复制书中段落。 |
| 七点式 | 作者 Dan Wells 的节目列出钩子、第一次转折、第一次压力、中点、第二次压力、第二次转折、解决。 | 每点必须改变主角处境；从结局反推钩子与中点。[Writing Excuses 7.41](https://writingexcuses.com/writing-excuses-7-41-seven-point-story-structure/) |
| 救猫咪 | 官方节拍表包含十五个节拍。 | 完整列出十五点，以篇幅比例作可调整建议，避免只写三幕。[Save the Cat 节拍表](https://savethecat.com/beat-mapper) |
| 五幕与 Freytag | Freytag 原著将行动分为引入、上升、顶点、下降和灾变，顶点之后有反向作用。 | 产品五幕采用入局、复杂化、中点改向、低谷、终局；Freytag 单独保留居中顶点与后果下行，避免两条完全相同。[Freytag 原著第二章第二节](https://www.briantriber.com/WritingSamples/Freytag_Drama/Freytag_11_Ch2_P2.html) |
| 四段式 | 业界存在多种四段划法，不能声称唯一标准。 | 本产品明确采用建立、被动应对、主动反击、解决，中点承担行动方式改变；属于产品操作口径。 |
| 基肖滕弧 | 用户名称按 Kishōtenketsu 起承转结收录：引入、发展、转向、综合。 | 通过新的观察角度改变理解，冲突可有但非必要；区别于本产品以目标阻碍为主的起承转合。[日本语言叙事实践研究](https://jll.pitt.edu/ojs/JLL/article/view/238/0) |
| 菲希特曲线 | 开局进入危机，多个危机累积至高潮，随后短暂收束。 | 让每次暂解制造更高代价，避免平均分幕；与 Freytag 不混称。[TCK Publishing 的方法说明](https://www.tckpublishing.com/fichtean-curve/) |
| 悬念循环 | 清楚的人物、处境和利害关系支持悬念。 | 提问、线索、局部兑现、下一问题，每轮兑现旧承诺。[SFWA 的悬念与清晰度](https://sfwa.org/2011/02/19/key-conditions-for-suspense-part-10-clarity-the-first-principle-of-plot/) |
| 爱情题材 | 类型爱情以核心恋爱关系及令人满足、乐观的情感结果为惯例。 | 模板默认给出关系解决；作者明确要求悲剧或开放结局时遵从作者，并标出类型承诺变化。[RWA 类型定义](https://www.rwa.org/about-romance-fiction) |

潮汐结构、环形、循环叙事等名称并无在本产品适用的唯一节拍版本，采用明确的产品定义：潮汐是压力与余波交替；环形是首尾意象回响；循环叙事是相似事件或跨代模式复现；科幻时间循环要求世界中的时间实际重置。非线性、逆时序、书信体、框架叙事、多线并行以时间排序、材料载体或视角编排区分。

“找锅型”按寻找表面责任者后追溯真实责任链解释；“嫁祸型”要求主动制造指向无辜者的证据；“替死鬼”要求代替真正目标死亡及身份误认。三个名称采用用户习惯用语，不冒称严格的学术分类。

## 覆盖与内容质量策略

重点库规划 74 条：通用 23、爱情 9、推理 9、奇幻 5、科幻 7、仙侠 6、都市 6、恐怖 5、历史 4。所有明确列举项各有一条主模板；使用旧稳定 ID 的三幕、场景与余波、仙侠退婚、仙侠废柴共四条不重复新增，净新增 70 条。

每条重点模板包含作者上下文输入、缺失信息处理、方法定义、专门步骤、输出交付物和自检；旧剧情也补同一执行合同。无需未绑定变量或联网查询即可拼贴。历史模板把史料事实、待核实点和虚构分别标明；推理模板先建真相与线索可见性，避免靠临时证据解释答案。

去重同时检查稳定 ID、同类别标题、标准化正文和去除公共合同后的方法主体；独立内容审查检查同义机制，防止仅换名字。私有作者模板属于作者数据，升级保持原文与版本，不自动去重或覆盖。
