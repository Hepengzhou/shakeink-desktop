## 作者使用与执行合同

模板从当前对话和同一向导的定位、主题、世界观、角色读取输入；作者明确设定优先，不把方法建议写成已经发生的事实。题材未定可以先给候选方向。缺少决定性信息时最多提出三个针对性问题并给标注“待作者确认”的可运行方案，不要求填满表格才继续。

重点模板包含 `【剧情】`、`【输入与缺省】`、`【方法】`、`【推进步骤】`、`【输出】`、`【自检】` 六部分。输出统一包含一句话主线、设定与假设、阶段表，以及该机制的专门交付物。阶段表含事件、动机、行动、结果与代价、读者信息或伏笔。一般输出 800–1600 字，长节拍或多线可适当延长；按方法节点数输出，不一律强制六到十个节点。既有剧情条目保留原问题并补合同，不引用外部模板占位符。

通用方法 channels/genres/tags 留空，适配现有筛选兜底；题材模板 channels 留空，不以性别限制题材。genres 与 tags 使用现有 taxonomy 词表：爱情映射现代言情、古风言情等；仙侠映射仙侠和仙侠奇缘；恐怖映射灵异及悬疑。不增加自定义字段到 portable schema，不修改数据库或 UI 分类法。

## 技术方案与变更范围

1. 在 `src/lib/creation-wizard/templates/plot-library.ts` 定义类型化重点条目与通用提示词组装器。每条有独立的方法、步骤和交付物。四个既有 ID 使用新正文，其余追加一次。
2. 在 `templates/curation.ts` 明确修订审查发现的旧同义条目，保留稳定 ID；给既有剧情补执行合同。跨类别同名改为表达各自任务的标题。`templates/index.ts` 聚合真实语料，既有消费者不变。
3. 使用原 `LocalTemplateLibrary.initialize()` 的精确 hash 更新：旧内置原样升级、旧内置作者修改或停用保留、用户副本保留、新 ID 只加入一次。实际 PGlite 升级及重开测试验证该链路。
4. 测试源码、模板筛选与拼贴、portable schema、真实本地 dispatcher、真实 React 向导和 Windows Electron 对应入口。真实 Electron 验证隔离数据根、无默认模型、模板详情、拼贴与离线重启落盘；不访问真实作者数据。
5. 仅新增本轮台账字段，保留 `requirements-traceability.json` 与 `migration-map.json` 已有未提交内容。不会改动其他任务正在修改的工作台组件。

## 去重标准

完整500条内置库检查各自命名空间ID唯一、同类标题唯一、跨集合标准化正文唯一；29条服务提示词的变量按其原声明与renderPrompt合同验证，不要求删除合法变量。重点库每条方法主体唯一。内容审核逐对区分目标、触发条件、推进机制和交付物；原囤货组区分储备准备、庇护所分配治理和公众预警，掉马区分累进暴露和身份义务冲突，追悔区分道歉修复和军职与家庭时间表协商。三幕的重复旧条目改为场景与余波，不删除 ID。独立现状审核指出的主题、世界观强同义条目也定向改写。

主题、世界观、角色可以围绕同一母题，但必须执行不同任务。用户自定义内容的重复不由应用擅自删除；本次无重复验收范围为交付的内置提示词与创作模板。

## 阶段顺序与验收边界

调研和本设计完成后先做独立技术方案审核，再写并独立审核定向测试用例，先运行 RED，之后实现、独立 code review、定向 GREEN 与真实目标验证，最后输出测试和总结。按用户本次要求，只执行本目标相关的用例，不运行全库或全流回归。

“可跑通”分别证明：每条正文完整且无未绑定变量；全部重点条目经真实本地持久化、读取、导出导入和草稿拼贴；真实组件与 Electron 入口能消费新增语料。供应商生成是模型非确定行为，仓库默认无模型；没有作者提供的真实供应商时，不把受控输出或静态内容审核写成真实模型生成通过。
