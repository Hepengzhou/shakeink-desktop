# 剧情模板库定向测试用例

本轮只验证新增语料、去重修订及其既有消费路径。全部测试使用隔离目录；真实作者资料与 Key 不进入用例。按独立方案和用例审核后 RED → 实现 → 独立代码审核 → GREEN 与 Windows Electron 验证推进。

| 编号 | 验证对象 | 可观察结果 |
| --- | --- | --- |
| PLX01 | 独立 coverage.json 九组覆盖 | 每个明确项对应唯一实际剧情 ID；各组至少达到19/7/7/3/5/4/4/3/2；本轮74重点、70新增、471总条目、160剧情 |
| PLX02 | 每条重点及全部旧剧情内容 | Zod schema通过；方法、步骤、输入缺省、输出、自检完整；无未绑定变量、演示标记、undefined、TODO；全文与元数据均可拼贴 |
| PLX03 | 全500条内置库去重 | 471创作模板加29服务提示词；各自命名空间ID、同类别标题、跨集合标准化正文无重复；公共执行合同剥离后重点方法主体仍唯一；服务提示词变量按原声明合同验证；独立审核对强同义条目逐对判定 |
| PLX04 | 实际过滤 | 重点通用模板在两频道、所有题材、篇幅下可见；题材模板经现taxonomy合法路径可见，不误标未知题材/标签；原题材过滤仍能排除不相关专门模板 |
| PLX05 | 全74条单独与四环节拼贴 | prompt保持完整，定位先于主题/世界观/角色/剧情，无变量丢失；不产生网络调用或自动发送 |
| PLX06 | 方法特征 | 救猫咪十五节点、Vogler十二阶段、七点七节点有完整约束；英雄/作家、五幕/Freytag、环形/循环/时间循环、找锅/嫁祸/替死鬼各有不同交付物 |
| PLX07 | 真实PGlite新增与升级 | 从原401内置启动，升级后新增70条且原ID不丢；原样旧剧情升级并留历史；作者修改、停用、用户副本保持原文、来源、版本和状态；重复初始化不增加revision |
| PLX08 | 真实PGlite重开与portable | 关闭并重新打开隔离库，471条内置持续存在；全部74条导出通过4MiB上限和portable schema；新库导入副本或keep后正文保持完整，无默认模型/凭据混入 |
| PLX09 | 原React向导实际点击 | 真实CreateNovelDialog加载由实际库导出的语料；剧情分类卡片数量、双击详情、使用模板、确定草稿保持原文与autoSend禁用；无模型不妨碍准备草稿；爱情/仙侠/科幻筛选可找到对应卡片 |
| PLX10 | Windows Electron真实目标 | 重建正式renderer/worker后以隔离根启动，实际原生模板入口看到新增条目、查看完整正文，原创作向导拼贴新增剧情草稿；离线重启后条目和作者停用/修改仍持久；无HTTP监听服务器，无供应商请求 |

执行目录为 `tests/unit/plot-template-library.test.ts`、`tests/integration/plot-template-library.test.ts`、`tests/browser/plot-template-library.test.ts` 和 `scripts/verify-plot-template-library.mjs`。既有模板管理、向导与dispatcher相关测试可定向合跑；旧401硬编码断言改为实际内置总数。禁止 npm test、全浏览器、全业务/全流测试。编译只为本轮语料进入真实Electron包，不计为全流测试。

静态正文约束和本地执行测试证明模板能够入库、筛选、拼贴及消费，不证明每个供应商的创作质量；供应商未配置时不伪造生成成功。
