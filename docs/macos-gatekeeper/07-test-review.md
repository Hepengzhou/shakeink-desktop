## 审核补强及关闭记录

方案审核要求无 asar 下的原生子项逐个核验，及解压前链接关系检查；MACREL-05/09 已明确相关失败和有效 Framework 链接正例。

本轮另要求两个明确断言，均已在用例文档中补齐并复核：

- MACREL-08：缺少外部预期 Team、有效但异 Team 的签名必须拒绝，清单自报 Team 不得替代外部信任期望。
- MACREL-09：重复原始 ZIP 路径及文件/目录路径冲突必须在解压前拒绝，避免预检对象与实际写入对象不一致。

上述均已关闭，不增加业务代码修改范围。实现 code review 时需核对这些断言有实际测试体、能在相应缺陷下失败，不能只用测试标题或命令调用次数代替。

## 执行与结果口径

本次只读取文档和限定范围源码，未运行应用、访问凭据/用户数据或修改产品；唯一新增文件为本审核记录。下一步应保存旧实现对新断言的 RED 结果，再实现并取得 GREEN，随后独立 code review。

MACREL-03 至 10 的受控命令端口只验证控制流/失败传播，不能证明 Apple 签名或公证真实通过。MACREL-11 的预期失败不能抵消 MACREL-14 的正例要求。真实身份/认证和目标环境未具备或未执行时，MACREL-14/15 必须保持待完成；用户要求的全部校验通过仍是最终完成条件。
