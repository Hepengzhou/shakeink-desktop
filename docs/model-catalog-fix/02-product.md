# 产品规则与技术方案：可信模型目录

前置产物：[调研](01-research.md)。本轮不改变批准的表单布局和单选交互。

## 用户行为

1. 首次无 Key 时只显示本次有官方来源及核对日期的内置种子。允许供应商种子较少或为空；空目录提示填写 Key 后刷新，不会以“全部模型”宣传种子。
2. 输入 API Key 并展开模型列表，或主动点击刷新，读取官方目录。成功取得完整分页结果后，该范围的列表被替换，缺失/下线/不可用项被移除；已选项若被移除则清空选择和能力参数，提示重新选择。
3. 更新目录立即持久化；取消配置只取消模型草稿，不撤销已成功更新的公开目录。关闭应用后无 Key/离线重启可读取最新快照，移除项不能被静态种子或已有模型配置回插。
4. 已保存的旧模型记录不自动删除、不修改 Key；编辑时型号不在最新目录则要求重新选择，不能保存或测试该不可用型号。自定义供应商保留手填模式，不污染内置目录。
5. 目录查询失败保留此前可信目录；不完整分页/非法响应/取消/迟到结果均不覆盖。能力分类未知的型号不显示为可选项，界面据实说明。
6. 快照不代表 Key 的调用授权；刷新后更换 Key 仍保留公开目录，但不能延续订阅限定型号的账户授权。缓存加载期间暂不显示候选，防止旧种子短暂复活。读写失败显示可理解错误，不宣称持久化完成。

## 实施范围

- `desktop/shared/builtin-model-catalog.ts`：仅使用逐条官方核对的种子；权威目录替换；保留种子能力补充及生命周期过滤，但不回补缺失 ID。
- `desktop/shared/model-catalog.ts`：增加目录 scope、权威枚举标记、可持久化快照契约。
- 新 `desktop/main/model-catalog-repository.ts`：供应商/类别/协议/标准化端点隔离，独立 VersionedStore 串行原子提交，严格白名单字段；不存 Key、请求正文、账户授权或供应商错误正文。记录时间与已确认可选型号；缓存恢复时 permission 为 unknown，订阅授权不缓存。
- `desktop/main/model-configuration.ts` 与 adapters：停止静态回补；所有分页成功后才标记权威。通过服务回调持久化，在提交前复查操作仍有效；读写失败有固定错误。
- `desktop/main/index.ts`、`desktop/preload/index.ts`、`desktop/shared/ipc.ts`：可信 IPC 只读目录；在现有数据根写入 `model-catalogs.json`，复用 metadataWrites 和根迁移闭锁。服务执行期间更新计入活动操作。
- `ModelConfigurationDialog.tsx`：按 scope 读取缓存并隔离迟到结果；刷新替换/清空失效选择，禁止旧记录回插；用户草稿仍手动保存。
