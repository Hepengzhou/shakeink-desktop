# 模型目录修复专项测试用例

前置产物：[调研](01-research.md)、[产品/技术方案](02-product.md)。仅执行下列本轮专项；禁止全量测试。公开夹具只用于验证协议与状态行为，不作为供应商真实可调用证据。

| ID | 步骤/覆盖 | 预期 | 层次 |
| --- | --- | --- | --- |
| MC-01 | 逐条检查内置种子的供应商/类别/来源/日期，与独立调研来源比对；检查已下线腾讯 ID | 只含有官方证据且类别可用的 ID；不含已下线型号 | 静态契约、研究审核 |
| MC-02 | 对全部预设范围用完整权威目录只返回一个内置 ID；服务对 OpenAI/智谱/MiniMax/火山分别只返回已知一项 | 缺失内置不回补；保留当前 ID 能力，不混入其他类别 | 单元/协议 |
| MC-03 | 官方完整目录为空，保存后重新创建目录仓库读取 | 空候选保持为空；无种子复活 | 单元/真实文件系统 |
| MC-04 | 不完整分页、401、网络错误、非法 JSON、取消、迟到响应；未知能力但分页完整 | 失败不覆盖旧快照；未知能力不猜测，权威完整结果可剔除缺失项 | 协议/真实文件系统 |
| MC-05 | 官方返回已下线时间/不可用条目、模态不符；明确腾讯 qwen3.5-flash/qwen3.5-plus 即使 live 误回传也须过滤；glm-5v-turbo 用显式时钟参数验证 2026-10-30 前后边界 | 不能选择已下线/不可用/错误类别；快照恢复同样过滤；未来边界测试不宣称当前真实退役 | 单元 |
| MC-06 | 刷新成功落盘，关闭仓库/新实例无 Key 读取；同一 scope 二次刷新新增与移除 | 使用最新目录；源码种子和旧快照不复活 | 真实文件系统 |
| MC-07 | 多供应商/类别/协议/端点、尾斜线、custom；审查落盘字节 | scope 隔离；custom 不写内置；无 Key/草稿/账户授权；恢复 permission=unknown | 单元/真实文件系统 |
| MC-08 | 写前取消、并发刷新反序、写入失败、读取损坏 | 写前操作有效性校验；后发操作胜出；失败不丢旧文件；损坏不回种子 | 单元/真实文件系统 |
| MC-09 | UI已选内置，成功刷新缺失该项；编辑已保存缺失型号；伪造旧选择保存/测试 | 清空草稿型号及能力；缺失项不回插；保存和测试被阻止；原记录不删 | 真实组件定向测试 |
| MC-10 | 缓存加载中/供应商切换/Key修改/缓存与在线刷新反序/关闭重开；刷新失败 | 不闪回旧种子、不接受迟到结果、不继承旧 Key 授权；失败保留可信目录 | 真实组件定向测试 |
| MC-11 | 单选选择/保存、取消配置、自定义手填路径 | 每次一个模型，草稿手动保存；取消不会保存模型或 Key；custom不受目录限制 | 真实组件定向测试 |
| MC-12 | Windows Electron隔离根写入已刷新快照，打开真实设置并无 Key 展开；关应用重启、离线再展开；空快照/旧配置缺失 | 最新候选可见，移除项不可见；无模型/Key写入；真实 IPC读盘，截图记录 | 真实 Windows Electron（官方接口仍为夹具，不声称真实供应商调用） |
| MC-13 | 隔离数据根包含目录文件，真实文件系统迁移到另一根 | 目录文件纳入所有权枚举及迁移；迁移后读取仍无缺失型号复活 | 真实文件系统 |

## 执行命令

- 红灯/绿灯：`node --import tsx --test tests/unit/model-catalog-refresh.test.ts`。
- 组件、种子、既有目录回归及迁移范围：`node --import tsx --test --test-name-pattern="MC-" tests/unit/model-settings.test.ts tests/unit/builtin-model-catalog.test.ts tests/unit/byok-catalog.test.ts tests/unit/data-root.test.ts`（其他用例不执行）。
- 类型检查：`npm run typecheck`、`npm run typecheck:foundation`，属于静态检查，不执行全量用例。
- 构建 UI/主进程后：`node --import tsx scripts/verify-model-catalog-refresh.mjs`。仅目录相关目标验证，不执行现有全量脚本。
