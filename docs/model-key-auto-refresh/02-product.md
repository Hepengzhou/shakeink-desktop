# 模型目录：Key 输入自动刷新与失效选择自动替换（产品规则）

基线：`docs/model-catalog-fix/02-product.md`（MC 组规则）。本文件只记录本次修改覆盖的两条行为；其余 MC 规则不变。

## 修改动因

配置文本/文生图模型时，用户填入或更新 API Key 后必须手动点"刷新模型列表"才能看到该 Key 对应的官方目录；刷新后若已选型号被剔除，选择被清空，需要重新手动选择。要求改为：

1. 填入或更新 API Key 后**自动**刷新模型列表，无需点击按钮。
2. 刷新后若当前已选型号变为不可用，立刻剔除并自动替换为下一个可用型号。

## 规则

1. **自动刷新触发**：仅 API Key 输入框的用户编辑（键入/粘贴/清空/更新）触发；仅当供应商属于当前类别的内置供应商列表时生效（旧记录的 legacy 供应商不自动刷新，定时器回调按 `presetsFor(kind)` 复核；custom 另由 `discover()` 内守卫兜底空转）。防抖约 500ms 合并连续输入，以最后一次输入的 Key 与当前供应商/协议/端点为准发起 `discoverModels`。实现上由计数器 effect 调度，`keyRefresh === 0` 时直接返回，**挂载与重开对话框本身不触发**。
2. **不触发的情形**：自定义供应商（无目录接口）；对话框初次打开/重开；已保存模型的 Key 回填揭示（非用户输入）；Key 为空且无可复用已存凭据；供应商/协议/端点被改（先取消挂起的自动刷新，Key 已清空则不刷新）；切换"选择已有模型"、导航离开、对话框关闭/挂起；测试连接或保存进行中（沿用 `unavailable()` 守卫）；确认待重试（confirmationPending）期间（回调以 ref 复查为准，防止过期闭包）。
3. **进行中语义**：自动刷新与手动刷新/展开列表共用同一条 `discover` 通道与取消机制；`discover()` 入口先取消挂起的自动刷新定时器，已在进行的目录请求不被重复发起（`discovery.current` 守卫），新的 Key 编辑取消旧请求。
4. **失效选择自动替换（仅刷新路径）**：刷新（自动、手动按钮、展开列表触发）返回权威/完整目录后，若当前已选型号不在新目录中：自动替换为目录中下一个可用且未按同供应商+端点+类别添加过的型号，同步名称/上下文/思维档，并提示"原选型号已不在当前目录中，已替换为下一个可用模型。"；无可用替代时保持旧语义——清空选择与能力参数，提示重新选择，保存/测试被阻止。
5. **缓存读取路径不变**：打开对话框读取本地缓存目录（非刷新）时，已保存旧记录的型号若不在缓存目录中，仍清空并要求重新选择，不能保存或测试该不可用型号（MC 规则 4 不变）。
6. 手动"刷新模型列表"按钮保留，用于出错后重试；提示文案更新为"填写或更新 API Key 后自动刷新"。

## 界面文案

- 目录说明：`显示已核对的内置目录或上次刷新的官方目录；填写或更新 API Key 后自动刷新。调用权限取决于当前 Key。`
- 替换提示：`原选型号已不在当前目录中，已替换为下一个可用模型。`
- 无替代时沿用：`原选型号已不在当前目录中，请重新选择可用模型。`
