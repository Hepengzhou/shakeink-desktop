## 实际断言和结果口径

- 架构应在真实 Mach-O 文件上检查；bundle 目录不能直接充当 lipo 对象。签名参数无 runtime 仍须由实际签名 flags 验证，实际无 Team/Authority 和资源封印不能被受控 display 文本替代真实产物证据。
- spctl/syspolicy 应保留退出码及实际拒绝类别。工具内部错误、不可用或超时应记检查失败/未验证，不能当成“符合预期的未公证拒绝”，也不能计正式信任通过。
- 网络控制负例应证明失败来自隔离策略：采用有效受控对照或明确的策略拒绝证据，并证明本地控制通道仍可用。单纯的 DNS/连接失败不能证明隔离生效；若覆盖不足，按实际层级记录。
- 目标机手动例外由用户本人决定，说明使用“如果系统显示此入口”；缺入口时保留待诊断状态，不把全局关闭 Gatekeeper 或清除隔离当作测试通过条件。
- 启动、退出、重开和篡改均使用本轮自有临时目录。原正常实例、真实用户数据和已封存坏样本保持原状；各阶段失败后，成功清单及说明必须准确反映真实结果。

这些是现有用例“真实结果、触发阶段、隔离范围”的执行解释，不增加业务修改范围或新的审批环节。临时测试验收仍不能代替正式 Developer ID/公证，未执行的目标系统与全量回归项目不得随用例设计通过而关闭。
