# Ad-hoc 临时测试 DMG 方案独立审核

日期：2026-10-16。受审产物：[01-plan.md](01-plan.md)。本次仅阅读方案及相关 Apple 官方说明；未操作 UI、钥匙串、账户或用户数据，未改产品或安装包。唯一写入文件为本审核记录。

**结论：方案通过，无方案阻断意见，可进入测试用例编写及独立审核；用例通过后再 TDD 实现。** 这是用户明确授权的临时测试路径，不能将其结果作为正式 Developer ID、公证或最终目标系统验收通过。

## 核查结论

| 核查项 | 结论 |
| --- | --- |
| 与正式发布隔离 | 独立入口与模块、内存中派生配置、唯一 adhoc staging/产物目录；正式发布配置、入口、签名公证模块和 entitlement 文件均在不修改清单内。只新增 npm 命令，保留正式预检/发布/重验门。 |
| 用户范围 | 仅本机 macOS arm64；不申请证书、不读取钥匙串、不调用 Apple 认证，不改业务组件、IPC、数据库和 renderer sandbox；旧坏包和预存修改按散列保留。 |
| 签名方式 | 先完成构建、本地化、资源组装，再扫描实际 Mach-O 与嵌套 bundle，由内向外逐个 Ad-hoc 签名，最后签外层 app；不用 deep 代替签名顺序。无身份、无安全时间戳、临时 non-hardened 的边界明确。 |
| 完整性门 | 每个原生代码对象校验架构和签名，顶层额外 deep/strict；要求实际 ad-hoc、无 Developer ID/Team、最小 JIT 与有效资源封印。签名失败、内部损坏或不安全链接不能继续产包。 |
| 资源与业务保护 | 继续使用现有资源、依赖和本地化检查，签名后不改 app 资源。启动测试只使用从实际 DMG 复制到自有临时目录的 app 及隔离数据根，不接触真实作品或配置。 |
| DMG 容器 | 明确容器不签名，hdiutil 校验只证明容器完整性；内层 app 的 Ad-hoc 完整性不冒充容器开发者身份或 Apple 公证。说明位于 app 外，避免破坏资源封印。 |
| 挂载与清理 | 只读挂载、临时复制、重复校验；只清理所属临时资源，detach 失败保留目录，不递归删除可能仍挂载的路径。 |
| 结果与分发边界 | 使用 adhoc-test 文件名及独立临时清单，不使用正式 verified 格式，不生成正式更新元数据、不自动发布。spctl/syspolicy 的拒绝与完整性检查结果分别记录。 |
| 网络、系统及全量验收 | 网络隔离先证明有效再命名范围；renderer 拦截不能冒充全进程断网。开发机与 15.7.5/M4 目标分开，下载隔离和例外入口尚未验证就保持待验；此前 core 失败不由启动冒烟抵消。 |

Apple 对嵌套签名及签名后资源不可修改的说明支持该签名顺序；DMG 的签名建议使用 Developer ID，临时方案没有假称已满足它。[TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)

Apple 将签名身份、公证和用户手动例外作为不同机制。安装说明应准确表述单个应用可能提供的例外，不能保证目标系统一定出现“仍要打开”。[Apple 安全打开 App](https://support.apple.com/en-au/102445)

## 实现及下一轮用例应直接落实的断言

- 验证实际签名 flags 没有 hardened runtime、没有 Developer ID Authority/Team；不能只凭 builder 派生配置中的 false 就判断最终签名状态。
- 检查 Mach-O 文件的架构；bundle 的架构应由真实可执行文件判定，不能对目录直接用 lipo。Resources 中的 `.node`、`.dylib`、无扩展名 Mach-O 不能遗漏。
- 从 DMG 复制后在启动前重验封印，进程正常退出/重新打开后再次验证；启动失败应明确失败，不能输出“启动通过”的清单或说明。所有临时成功状态必须与真实执行结果相符。
- 单元端口只验证顺序和失败传播，最终 DMG 应用的真实 codesign 完整性结果单独保留；Gatekeeper 拒绝不能被转写为正式信任通过，也不能因此清除下载隔离或修改全局设置。
- 在用例阶段冻结必要的边界测试具体文件范围。安装说明不代用户确认安全例外；无例外入口或仍有异常时停止并收集针对该包的诊断，不指导全局关闭 Gatekeeper。

上述均为原方案已有边界的验收方式，没有增加业务改动范围。本审核不证明临时包已经构建、签名或启动成功；真实安装包、隔离首启及回归结果须由后续执行记录证明，未执行项保持未验证。
