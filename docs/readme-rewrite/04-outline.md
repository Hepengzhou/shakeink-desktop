## 一、整体方向

- **定位**：面向长篇小说的本地 AI 创作工作台。
- **主标题**：玄印写作 · ShakeInk，副标识「桌面版」。
- **Slogan**：**让灵感成章，让故事生长。**
- **主要读者**：中文小说作者；先让作者看懂创作价值，再给开发者运行入口。
- **篇幅**：正文约 1,800–2,400 个中文字，另计命令、表格与图注；核心亮点占主要篇幅。每项亮点用约 80–140 字讲清使用场景、实际做法与作者收益。
- **风格**：克制、温润、留白充分。宣纸为主，玄墨图穿插；保留项目品牌。不把研发台账或技术栈堆到首屏。

## 四、核心亮点：README 的主体（纯文字，不插图）

### 1. 让 AI 带着你的故事思考

从「一次次向模型重讲设定」切入，介绍对话中用 `@` 带入章节、角色等资料、用 `/` 选择创作命令，以及自行配置文本和图像模型。强调作者选择任务与稿件的主动权；不写“一键生成好小说”“永不跑偏”或免费额度。

本节用清晰短文说明，不插图，也不把视觉展示中的业务截图当成 AI 对话证据或补造回复。说明 AI 功能需要自己的模型配置，远程调用会向所配置服务发送相关请求。

### 2. 人物的选择，从内心长出来

以陆照微「寻找父亲」与「让被抹去的人重新拥有名字」的两层动机为例，介绍身份、心理、能力、弧线和关系如何构成持续可查的人物档案。重点是人物行为与信念的联系。

本项只用文字介绍；对应人物图集中在前面的视觉展示，不在此重复。

### 3. 给世界立规矩，也给故事留根基

介绍世界与子区域、地理/社会设定的层级组织。用澄江流域、桂渡镇与魂灯规则说明：地名、制度和能力代价可以围绕同一故事查阅与维护。避免“自动杜绝设定冲突”的绝对承诺。

本项只用文字介绍；不引用世界截图，也不声称已有世界地图。

### 4. 故事如何发生，读者何时知道

重点解释世界线管理事件的发生顺序，叙事线组织讲述顺序、人物视角和卷章关联。以追查旧案的四个事件说明长篇规划价值：可以看清时间、人物与章节的联系，再安排信息揭露。

本项只用文字介绍；视觉展示中的规划图仅代表世界线及其章节关联，不误称同时展示完整叙事线面板。

### 5. 埋下的每条线，都能找到来处

围绕「伏笔写在哪、提过几次、准备何时回收」展开，介绍状态、回收计划、触点链与正文引用。用灯籍下的“七”字对应第七号船说明从线索回到原文的用途。

介绍 Markdown 编辑、分屏与预览、卷章组织、稿件版本及四种导出格式。以《汴河来信》的北宋市井正文体现另一种题材，强调创作资料最终汇入可阅读的正文。

## 六、安装与运行

主要入口为源码运行。正文撰写时复核仓库 Releases；若仍无公开 Release，不放「立即下载」或虚构版本链接。

前置要求：Node.js 24、npm、Git；首次安装依赖与构建需要网络。跨 macOS/Windows 尽量使用同一组命令：

```sh
git clone https://github.com/mySingleLive/shakeink-desktop.git
cd shakeink-desktop
npm ci
npx playwright install chromium
npm run generate:commands
npm run build
npm start
```

其中 Chromium 与命令目录生成用于本次发现的首次构建问题；产品工作台仍由 Electron 本地协议运行，无需启动 HTTP 服务或外部数据库。AI 另外配置模型与密钥。

将安装包构建放进一个 `details`：在匹配目标 OS/CPU 的机器安装依赖并构建；`npm run package:dir` / `npm run package`，产物位于 `release/`。链接已有验证记录说明当前签名/公证与平台验收状态，不把此处变成工程操作手册。
