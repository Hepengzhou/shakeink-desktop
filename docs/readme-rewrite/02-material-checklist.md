## 展示内容标准

- 《照夜渡》至少一卷四章、三位角色、一个世界及子区域、两个场景、三条伏笔；至少两章有自然正文。第一章的灯籍异常与后续章节/伏笔保持一致。
- 《汴河来信》至少一卷三章、三位角色、一个时代/城市设定、两个场景；至少两章有自然正文。人物身份、货币/商品和运河情节保持合理，不凭空出现现代设备。
- 章节正文以完整场景推进，避免将几行简介重复数十次凑字数。截图里能看到至少 3 个自然段，不堆 Markdown 装饰。
- 显示笔名为原创虚构笔名，不填写真实邮箱、电话、密钥、用户名或绝对路径。
- 不预写冒充供应商生成的 AI 消息，不伪造任务完成、评审分数或调用成本；需要展示的人工样稿在素材说明与 README 对应图片附近同时标明。

## 拍摄与后期

1. 用 Node 24 安装并构建当前仓库；记录命令和实际结果。不要为了截图更改业务代码。
2. 生成独立临时目录，写入上述两本作品并通过真实服务读回检查；应用使用 `SHAKEINK_TEST_ROOT`，启动后核对实际根目录与初始零模型；用户随后手动配置模型的已有演示库，须显式 `--resume-demo` 严格核验后恢复，助手不调用模型。
3. 真实 macOS Electron 窗口，拟采用约 1440 × 960 逻辑像素（以屏幕实际容纳尺寸为准），宣纸为主、墨色为辅。保持统一比例、字号及缩放。
4. 使用原生窗口截图，含完整真实关闭、最小化、最大化三按钮（允许系统失焦灰色）和完整窗口边界。webContents/Playwright 页面截图仅可做内部检查，不能作为最终图片。
5. 通过真实 UI 或应用现有设置/恢复接口选择面板；允许导入原创业务数据，禁止改 DOM、CSS 或画面文本。关闭无关应用弹窗，不擦除错误。
6. 等待数据和字体稳定；每张最终图人工放大检查：无错误、警告、失败 toast、调试条、隐私、空白主内容或裁切的窗控。光标移出内容区。
7. 保留原始像素与比例，必要时仅无损压缩。原图可直接用于 README，无外部 CDN；记录实际文件大小，优先清晰度。
8. 核对构建白名单不含 `docs/readme-assets` 与 `scripts/readme`，展示内容不会随应用发布。退出本次启动的应用，仅清理本次创建的临时资源。

## 素材审核清单

独立子代理在制作前审清单，制作后逐张看最终图并审查数据/脚本：

- 顺序与目标是否完整；各卖点是否有对应图片与真实实现。
- 每图是否包括真实 macOS 三个按钮；不能只有内容页面截图。
- 两题材是否有足够合理的内容；人物、章名、设定、伏笔有无矛盾。
- 是否存在未经证明的 AI 输出、完成结果、平台兼容或安全承诺。
- 是否有错误/警告、私人资料、真实 Key、本机路径、测试占位词。
- 文件、许可、清晰度、布局和 README 相对路径是否适合公开仓库。

制作前准入标准：清单无阻断/高优先级问题，范围、来源、隔离和拍摄规则足够明确。此阶段不声称看过尚未制作的图片。

制作后通过标准：所有必选图实际存在、独立子代理逐图看图且无阻断/高优先级问题。审核文档单独写入 `docs/readme-rewrite/reviews/`。素材审核通过后才进入大纲，随后等待用户批准。
