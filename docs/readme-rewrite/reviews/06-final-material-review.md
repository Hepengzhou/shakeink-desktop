## 本轮脚本与数据准备差异

1. **恢复与模型数量门保持。** 默认 `allowConfiguredModels = false`，默认启动仍拒绝已有模型的库；仅显式 `--resume-demo` 允许恢复用户配置后的同一演示库，其余临时根、fixture、内容哈希、catalog、目录身份与 bootstrap 指针检查不变。计数替代深比较，不输出配置对象；没有解密、打印、修改或调用模型的实现。
2. **只采集真实窗口与原像素。** Swift 按本次 PID、工作台标题、layer 0 选择唯一窗口；`capture-native.mjs` 只调用获准的系统截图并 `copyFile` 保存原文件。Sharp 仅分析元数据和像素，不涂抹、拼贴、补画窗控或擦除警告。共享条预检保留人工审核门。
3. **元数据与真实选景一致。** A07 已改为“历史穿越正文预览”；A08 标为首次运行主题选择且 `book: null`。A06 拍摄记录与图中实际第一伏笔一致。六张业务图记录模型数量 2，A08 为 0，没有把计数当成凭据内容写入公开素材。
4. **A08 初态和排序准备合理。** `--first-run` 仅在新建空临时目录中把 onboarding 设为产品原始未完成值 `null`，不复制已有模型或个人设置。两书准备完成后，生成器通过该原创作品所属 Workspaces/Prisma 更新第一本小说的 `updatedAt` 为当前真实时间，使正式列表把正文所属作品排首；没有伪造未来时间、改 UI 排序逻辑、改人物/正文或改源产品。最终 A08 已实际看到正确目录，排序调整达到目的。
