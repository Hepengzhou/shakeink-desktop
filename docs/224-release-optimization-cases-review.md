## RED 与证据要求

新增回归先在原代码证明命中缺陷或缺少行为（例如未生成 runtime manifest、未经裁剪的冗余依赖、启动 Monaco 导入、快照/实时优先级不满足），记录命令与明确失败断言，再实施获得 GREEN。仅因测试模块尚不存在而报 MODULE_NOT_FOUND 的 RED 不足以证明行为回归；若初始为该状态，应补出可对原流程执行的行为断言。负例须检查拒绝原因和输出副作用，不能只断言“抛了任意错误”。

低层真实 FS 测试负责可穷尽的解析和删除边界；Node 包探针负责无环境回退的实际依赖/持久化；真实 Electron 包负责运行、编辑器、快捷键、离线与交互。三者不能互相替代。为本次已删源码依赖或移出的许可证位置更新旧检查时，须保存同等或更强的运行/许可断言，并说明原断言为何不再对应正式架构；不能因原检查失败而直接删检查。

验收报告应逐个列明本清单 ID 的命令/证据/结果，未达体积、内存、启动或交互指标据实继续调查；未具备 Windows/Intel Mac、开发者签名/公证、真实下载隔离或供应商条件的条目单列未验，不能称全部目标系统通过。测试数据、导出与日志仅位于隔离目录，不读取用户作品与 Key。

本审核无待补的设计阻断项；执行时若上述必测条件未覆盖或失败，对应验收仍不通过。本次仅修改两个审核文档，没有修改产品代码或测试实现。
