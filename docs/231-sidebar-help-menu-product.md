# 侧栏用户菜单「帮助 / 问题反馈」产品文档（231）

日期：2026-10-19。调研见 `docs/230-sidebar-help-menu-research.md`。

## 需求（用户约束，逐条照录）

- 在左侧导航栏底部的用户弹出菜单中，在「设置」下方加入新的菜单项：「帮助」和「问题反馈」。
- 「帮助」菜单可以展开二级菜单：「官网」「产品介绍」「用户指南」「常见问题」，这些都是链接按钮，点击后都会在浏览器中打开对应的链接。
- 「问题反馈」菜单项和「设置」对话框中「关于」下的「问题反馈」按钮一样，在浏览器中链接到 GitHub 提交 issue 的地方。

## 用户故事

- 作为作者，我在使用玄印写作时想快速打开官网、产品介绍、用户指南或常见问题页面，不必先记住网址或离开当前思路去翻设置，所以我希望在侧栏底部账号菜单里一键打开。
- 作为作者，我遇到问题时想立即到 GitHub 提交 issue，账号菜单里与设置「关于」页一致的「问题反馈」入口让我少走路径。

## 功能规格

### 菜单位置与顺序

左侧导航栏底部账号弹出菜单（点击账号按钮展开，向上弹出），现有内容自上而下：用户信息 → 外观主题 → **设置 → 帮助 → 问题反馈**。新项紧邻「设置」下方，依次为「帮助」「问题反馈」，不新增分隔线，其余内容逐字不动。

### 菜单项行为

| 菜单项 | 形态 | 行为 | 打开地址 |
| --- | --- | --- | --- |
| 帮助 | 一级项，悬停/点击展开二级菜单（右侧箭头） | 展开二级菜单，自身不跳转 | — |
| ├ 官网 | 二级链接按钮 | 浏览器打开官网 | `https://shake.ink` |
| ├ 产品介绍 | 二级链接按钮 | 浏览器打开产品介绍 | `https://shake.ink/docs/introduction` |
| ├ 用户指南 | 二级链接按钮 | 浏览器打开用户指南 | `https://shake.ink/docs/guide` |
| └ 常见问题 | 二级链接按钮 | 浏览器打开常见问题 | `https://shake.ink/docs/faq` |
| 问题反馈 | 一级链接按钮 | 浏览器打开 GitHub 新建 issue 页（与设置「关于」页「问题反馈/填写反馈」按钮同一地址） | `https://github.com/mySingleLive/shakeink-desktop/issues/new/choose` |

- 二级菜单四项顺序固定为：官网、产品介绍、用户指南、常见问题。
- 点击任一链接按钮后菜单关闭，链接经主进程 `shell.openExternal` 交给系统默认浏览器；应用窗口不导航、不内嵌远程页面。
- 各菜单项带 Lucide 图标，与「外观」「设置」的视觉风格一致：帮助 `CircleHelp`、官网 `Globe`、产品介绍 `BookOpen`、用户指南 `BookOpenText`、常见问题 `CircleQuestionMark`、问题反馈 `MessageSquareWarning`。
- 菜单文案为真实固定文案，无示例/占位内容；无网络时由系统浏览器自身报错，应用内不新增提示文案。

### 命令与地址（实现映射，非界面文案）

| 界面项 | 命令 id | 地址常量 |
| --- | --- | --- |
| 官网 | `help.website`（既有） | `PROJECT_WEBSITE_URL` |
| 产品介绍 | `help.docs`（既有；该地址页面标题即「产品介绍」） | `PROJECT_DOCS_URL` |
| 用户指南 | `help.guide`（**新增**） | `PROJECT_GUIDE_URL`（**新增**） |
| 常见问题 | `help.faq`（既有） | `PROJECT_FAQ_URL` |
| 问题反馈 | `help.feedback`（既有） | 主进程内联地址（与「关于」页同一行代码路由） |

## 非目标（明确的范围边界）

- 不改动原生应用菜单的「帮助」菜单（仍为 官方网站/帮助文档/常见问题/问题反馈；Windows 末尾「关于玄印写作」）。
- 不改动设置对话框「关于」页的任何行与按钮。
- 不改动独立 About 窗口及其外链白名单（`PROJECT_EXTERNAL_LINKS` 维持四项）。
- 不为新命令绑定默认快捷键；快捷键设置页随之多一行「用户指南」展示项，与既有 help.* 一致。
- 不在应用内内嵌帮助内容、不新增离线帮助页。

## 验收标准

1. 账号弹出菜单中「设置」下方依次出现「帮助」「问题反馈」。
2. 「帮助」可展开二级菜单，依次为「官网」「产品介绍」「用户指南」「常见问题」。
3. 二级菜单四项点击后分别在浏览器打开上表对应地址；「问题反馈」点击后打开 GitHub 新建 issue 页，与设置「关于」页按钮同地址。
4. 所有打开均经系统浏览器，应用窗口自身不跳转。
5. 菜单既有内容（用户信息、外观、设置）行为不变。
